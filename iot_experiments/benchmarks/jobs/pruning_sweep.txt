# GPU-only (hello scan + cupdlpx master). Planted Monge instances (exact, no OT solver).

# QUESTION: with a *working* pruning strategy (hysteresis + regularized tie-break, the 4/4 winner),
#   how does |F| grow vs prune=none, and what does it cost in time and memory? Sweep the axis
#   parameters and compare every arm against its prune=none baseline (each job records both).
#
# READ-OUTS (in planting_sweep.json per record): max_support_over_m_plus_n, final_support_over_m_plus_n,
#   peak_memory_mb, mean master/scan seconds (from the trajectory), solve_seconds, converged, is_optimal.
#
# AXES (kept small on purpose -- one question per job):
#   prune strategy  : none | hysteresis | hysteresis+regularized
#   epsilon  (reg)  : 3e-5, 1e-4, 3e-4           (1e-4 works, 1e-6 fails -> locate the window)
#   tau_prune       : 1e-12, 1e-3, 1e-1          (1e-12 default; larger = more conservative)
#   time budget t   : 60, 300                    (60 = comparable to the no_prune batch; 300 = validated)
#   tie-break       : none | regularized
#   tol_sep         : 1e-9 (default) + one 1e-3 control   (was never tested; could cut |F| most)

#   n               : 3200, 12800, 51200         (51200 = the large run)
#   family/d/g      : quadratic, d=8, g=zero     (fixed)
