# validated + uncapped — GPU-only (hello scan + cupdlpx master, HELLO ground truth).
#
# Question this file answers: the `no_prune` sweep showed delta = 0 for every gmm_floored run
# (n = 3200/6400/12800) at all sizes, while uniform kept a small positive delta. That has TWO
# candidate explanations that are currently CONFOUNDED:
#   (a) GROUND TRUTH: HELLO's fractional pi_hat is not exactly optimal -> genuinely no margin;
#   (b) CAP: delta collapses at exactly the iteration where the master starts hitting the
#           20 s CuPDLPx cap (which none of the CLI could raise before 9250df9).
# This file separates them: raise the cap to 300 s AND turn on --validate (is_optimal, the
# authoritative exact-OT verdict, dense POT, only affordable up to n~7000).
#
# Read as:
#   - delta > 0 with the cap out of the way  -> earlier delta=0 was a cap artifact;
#   - delta = 0 AND is_optimal = True        -> delta=0 is a real property of the fractional
#                                               instance (major finding: no recoverable margin);
#   - is_optimal = False                     -> the GPU loop's theta does not make pi_hat
#                                               optimal (a real solver failure at that size).
# Note --validate uses dense POT (m*n <= 5e7), so n <= ~7000 only. n=12800 gmm runs are kept
# WITHOUT --validate as the uncapped continuation of the no_prune series.

# ---------------------------------------------------------------------------
# P1 — THE decisive run: fractional regime, cap 300, validated
# ---------------------------------------------------------------------------
# P1a: primary. Cheap, decisive. Does delta stay 0 once the cap can't bite?
python -m iot_experiments.gpu_bench.run_batch --batch e2e --gpu auto --family diagonal --marginal gmm_floored --sizes 3200 --point-dimension 8 --scans hello --masters cupdlpx --plan-backend hello --cupdlpx-time-limit 300 --max-iterations 12 --validate --out iot_experiments/gpu_bench/out/validated/V1_n3200_gmm_d8
# P1b: same at the largest size POT validation still covers (6400^2 = 4.1e7 < 5e7).
